# Processing a claim
The React/Vite application calls FastAPI over HTTP. The development build proxies /api to port 8000. The included compiled client can be served directly by the backend.

1. P1 normalizes and decomposes the statement, extracts qualifiers and proposes neutral and skeptical queries. With no key, explicit local heuristics supply search terms.
2. Retrieval runs bounded concurrent searches against Wikipedia and Crossref or Europe PMC. It tries FactCheck.org's public WordPress API only when allowed by its robots policy. The optional Google Fact Check Tools adapter uses a separate key and retrieves approved publishers' original article paragraphs. Finance and public affairs claims also check the PIB English press-release feed. The indexed local snapshot contains linked NASA, WHO, RBI, Full Fact and ABC News passages. SQLite caches adapter results for 24 hours. Titles alone do not count as evidence.
3. BeautifulSoup strips navigation and scripts. Sentences are chunked, near-duplicates are removed and TF-IDF unigram/bigram cosine similarity ranks each passage against each assertion. The rank uses 80% strongest relevance and 20% source indicators. P2 then assesses semantic relevance, including negation, numbers, and context.
4. Source weights live in backend/source_weights.json. Traceability contributes .15, visible publisher .12, author .08, publication date .08, topic-matched institution .30, relevant primary institutional statement .20 and scholarly indexing .12, capped at 1. Indexing alone does not establish a paper's quality. Unknown publication dates stay unknown.
5. P2 returns typed findings. Python checks assertion range, evidence IDs, nontrivial exact quote inclusion, per-assertion relevance and duplicates. Present-tense qualifiers such as “currently” require a dated passage within a conservative 90-day window. This heuristic cannot resolve all temporal language. Rejected items and reasons are stored.
6. The decision rule requires either one topic-matched primary source with score at least .70 or two distinct publishers scoring at least .40. Repeated passages, shared first authors and identical titles do not establish independent confirmation. Different labels on one assertion cause abstention. Every assertion needs coverage. A fully covered mix of supported and contradicted assertions can yield MISLEADING. P3 can accept the enforced result or abstain. Its cited IDs are checked again. Exact quotations are displayed from validated P2 findings. Generated explanatory prose still requires human review.
7. Confidence depends on coverage, minimum independent publisher count, relevance, source indicators, agreement and validation errors. High requires at least two qualified publishers for every assertion and strong passages. These are qualitative evidence grades.
8. SQLite stores reports, search terms, dated retrieval cache and experiment results. The single-process job queue exposes actual progress. The web client renders text through React, restricts links to retrieved HTTPS URLs, and exports complete JSON reports.

## Scope and failure modes
Search coverage varies substantially by subject, date and publisher. A query can yield no relevant document. Metadata, source scores, lexical overlap and genuine quotations cannot guarantee that an author or a model is correct. Syndication detection is approximate. Historical press releases describe their publication context. Reports separate local snapshots, cached responses and live results. Missing evidence, unresolved conflicts and failed AI comparison produce UNVERIFIABLE. With no configured model or explicit offline mode, only literal complete-sentence matches can support a conclusion under the same source rules. No benchmark verdicts are loaded into the production pipeline.

All search hosts are fixed. User-supplied URLs are never fetched. Optional article extraction restricts HTTPS hosts, rejects private IPs, pins the resolved address with TLS validation for the original host, rejects redirects, checks robots.txt and caps content bytes. Retrieved text is untrusted. JSON schemas, source-ID checks, backend-only credentials, per-client rate limits, size limits and timeouts constrain the pipeline. Prompt injection and semantic manipulation remain imperfectly detectable.
